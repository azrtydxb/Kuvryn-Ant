# F23 — Rust / Cargo contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

Cargo alternate-registry Web API, sparse HTTP index and Git index transport; crate archives and checksums.

- cargo: **1.99.1** ([release/source](https://api.github.com/repos/rust-lang/rust/releases/latest)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

cargo publish commits crate bytes and index metadata, with scoped registry token and owner policy. Yank/unyank mutates availability, not crate bytes.

## Consume and source support

cargo fetch/build consumes both sparse and Git index configurations from local/remote/replica feeds.

## Resolution policy

package-owner per canonical crate name

## Format-specific integrity and metadata

Index config points to authorized crate/download/API routes; keep dependency features/schema fields. Git index is generated protocol state, not arbitrary user repository hosting.

## Explicit non-goals

Public crates.io account/team/search ranking behavior and compiling crates server-side are excluded.

## Required client scenarios

- [ ] Publish and fetch a dependency chain with sparse and Git indexes, then verify checksum-preserving replica.
- [ ] Invalid checksum, ambiguous crate normalization or unauthorized yank cannot corrupt index state.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.
