# F15 — NuGet / Chocolatey contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

NuGet v3 service index/registration/flat-container/search/publish plus v2 OData package discovery/download/publish needed by Chocolatey.

- dotnet: **10.0.402** ([release/source](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json)).
- chocolatey: **2.7.4** ([release/source](https://api.github.com/repos/chocolatey/choco/releases/latest)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

dotnet nuget push and Chocolatey push accept nupkg; symbol ingestion supports snupkg and a documented legacy symbols.nupkg path, validating identity/PDB inventory.

## Consume and source support

dotnet restore and choco install consume packages; symbol lookup/download is separately exercised with Windows debugging tooling.

## Resolution policy

package-owner per case-normalized package ID

## Format-specific integrity and metadata

Normalize versions consistently across v2/v3; API keys and download auth share scopes. Symbol assets retain PDB identifiers, checksums and access policy; package scripts are never run on the server.

## Explicit non-goals

NuGet.org account/gallery APIs and executing Chocolatey scripts server-side are excluded. Symbol workflow requires Windows client evidence before claim.

## Required client scenarios

- [ ] Push/restore package through v3, install via v2 Chocolatey, and retrieve matching symbols.
- [ ] Mismatched symbol identity, unauthorized package/symbol request and version-normalization collision fail.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.
