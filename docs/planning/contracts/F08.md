# F08 — Docker / OCI contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

OCI Distribution 1.1 API and Docker Registry HTTP API v2 compatibility for schema-2/OCI images and multi-platform indexes.

- docker: **docker-v29.9.1** ([release/source](https://api.github.com/repos/moby/moby/releases/latest)).
- oras: **v1.3.4** ([release/source](https://api.github.com/repos/oras-project/oras/releases/latest)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

Docker push using scoped registry tokens; resumable blob upload, digest finalize and manifest/tag commit; validate referenced object closure.

## Consume and source support

Docker pull/tag/list behavior and manifest negotiation from local, remote pull-through and replica repositories.

## Resolution policy

package-owner per OCI repository

## Format-specific integrity and metadata

Manifest bytes are immutable by digest; tags are conditional mutable pointers. Cross-repository mount requires source read and destination publish permission. Return accurate upload offsets and range responses.

## Explicit non-goals

Docker schema-1 manifests, implicit upstream push and cloud-registry administrative API emulation are excluded.

## Required client scenarios

- [ ] Push/pull a multi-platform image and interrupt/resume a blob upload without corrupting digest identity.
- [ ] Reject unauthorized mount, missing referenced blob and conflicting immutable manifest; proxy preserves digest bytes.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.
