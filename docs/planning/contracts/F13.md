# F13 — Maven contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

Maven2 repository layout with POMs, maven-metadata.xml, release and timestamped snapshot assets and checksums.

- maven: **maven-3.10.0** ([release/source](https://api.github.com/repos/apache/maven/releases/latest)).
- gradle: **9.8.1** ([release/source](https://services.gradle.org/versions/current)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

Maven deploy and Gradle maven-publish upload a staged coordinate set; commit a version/index generation only after required metadata/assets validate.

## Consume and source support

Maven/Gradle resolve dependencies and plugins using local/remote/replica feeds and release/snapshot policy.

## Resolution policy

package-owner per groupId/artifactId; version-bound snapshot generation

## Format-specific integrity and metadata

Preserve client-required legacy checksum files alongside internal SHA-256; checksum compatibility is not a cryptographic trust upgrade. Metadata update races use generation checks.

## Explicit non-goals

No Maven Central account/staging API clone or build execution. Partial deployment must not look complete.

## Required client scenarios

- [ ] Deploy release and two timestamped snapshots, then resolve from Maven and Gradle with checksums.
- [ ] Concurrent metadata update cannot lose a version; incomplete deployment and bad checksum remain invisible.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.

## Delete and unlist (artifact core)

All deletion goes through `artifact.Service.Delete/Unlist/Relist`: delete permission, feed/namespace delete policy (`allowed`, `unlist_only`, `denied`, immutable releases), audit and outbox in the same transaction, replication tombstones, cache invalidation hook; bytes are only reclaimed later by garbage collection.

API only (Maven has no native delete route here): `DELETE {version}/` removes a version, `DELETE {version}/{file}` one asset (version goes with its last asset). maven-metadata.xml is generated.

Management API: `DELETE /api/v1/feeds/{id}/packages/{component}/versions/{version}?action=delete|unlist|relist`, `DELETE /api/v1/feeds/{id}/assets/{asset}`, MCP `delete_package_version`, console package drawer.
