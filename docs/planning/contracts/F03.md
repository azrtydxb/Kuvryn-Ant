# F03 — APT / Debian contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

Debian dists/pool repository layout with InRelease, Release/Release.gpg, Packages/Sources and SHA-256 by-hash.

- apt: **3.0.3** ([release/source](https://packages.debian.org/trixie/apt)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

Admin ingestion of .deb and source bundles (.dsc and referenced files) into distribution/component/architecture; publish one signed index generation.

## Consume and source support

apt update/install and apt source using local or byte-preserving remote/replica snapshots; support compressed index representations.

## Resolution policy

snapshot-owner per distribution/component/architecture

## Format-specific integrity and metadata

Keep by-hash generations reachable while readers complete. Remote trust and local signing keys are distinct. Source bundle references must be complete before publishing.

## Explicit non-goals

No arbitrary union of independently signed Release trees; translations/Contents generation and distro build-farm orchestration are not required initial workflows.

## Required client scenarios

- [ ] Ingest package/source bundle; update/install/source with trusted signing key and by-hash.
- [ ] Index update during concurrent download cannot yield hash-sum mismatch; tampered or expired metadata fails.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.

## Delete and unlist (artifact core)

All deletion goes through `artifact.Service.Delete/Unlist/Relist`: delete permission, feed/namespace delete policy (`allowed`, `unlist_only`, `denied`, immutable releases), audit and outbox in the same transaction, replication tombstones, cache invalidation hook; bytes are only reclaimed later by garbage collection.

Native API: `DELETE` on the pool path unlists the package from a new signed generation (core `Unlist`); bytes stay referenced until retention. Not an in-place delete.

Management API: `DELETE /api/v1/feeds/{id}/packages/{component}/versions/{version}?action=delete|unlist|relist`, `DELETE /api/v1/feeds/{id}/assets/{asset}`, MCP `delete_package_version`, console package drawer.
