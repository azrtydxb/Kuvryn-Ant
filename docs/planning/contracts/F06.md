# F06 — Conan contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

Conan 2 remote API with recipe revisions, package IDs and package revisions.

- conan: **2.33.0** ([release/source](https://pypi.org/pypi/conan/json)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

conan upload publishes recipes and binary packages with revisions/manifests; validate referenced files and immutable revision identity.

## Consume and source support

conan list/install/download resolves revision-aware recipes and binaries via local, remote cache and replica.

## Resolution policy

package-owner per recipe reference

## Format-specific integrity and metadata

Preserve revision chronology for latest resolution; auth tokens map to shared scopes. Retention cannot drop recipe/manifests needed by retained binaries.

## Explicit non-goals

Conan 1 compatibility and binary compilation are excluded initially; not a claim of arbitrary custom server plugins.

## Required client scenarios

- [ ] Upload two revisions and two binary package IDs; resolve both pinned and latest revisions.
- [ ] Manifest mismatch or conflicting revision bytes fail; replicated revision order matches source.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.
