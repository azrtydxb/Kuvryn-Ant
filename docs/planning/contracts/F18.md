# F18 — Pub / Flutter contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

Hosted Pub Repository Specification v2 with package/version metadata, archives, archive hashes and staged publish.

- dart: **3.13.5** ([release/source](https://storage.googleapis.com/dart-archive/channels/stable/release/latest/VERSION)).
- flutter: **3.47.0** ([release/source](https://docs.flutter.dev/release/release-notes)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

dart pub publish to publish_to uses token auth and upload/finalize behavior; validate pubspec and archive before visibility.

## Consume and source support

dart pub get and flutter pub get resolve packages from local, remote and replica hosted repositories.

## Resolution policy

package-owner per package name

## Format-specific integrity and metadata

Preserve archive SHA-256 and retraction/discontinuation metadata; do not silently replace a published version. Credentials remain tied to hosted origin.

## Explicit non-goals

Pub.dev social/scoring/account APIs and server-side package execution are excluded.

## Required client scenarios

- [ ] Publish a dependency chain and resolve through Dart and Flutter with lockfile hashes.
- [ ] Failed finalize, archive tampering and unauthorized token reuse cannot produce installable content.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.
