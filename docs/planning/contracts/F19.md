# F19 — PyPI contract

Status: Defined for implementation; not yet conformance-tested. Revision 1, 2026-10-18.

## Client and protocol baseline

Simple Repository API HTML and JSON representations, normalized project names, wheel/sdist files, hashes, yanked and requires-python metadata.

- pip: **26.2.1** ([release/source](https://pypi.org/pypi/pip/json)).
- twine: **7.0.0** ([release/source](https://pypi.org/pypi/twine/json)).

Pin actual downloaded artifact digests in the conformance fixture lock; these are deliberately selected baseline versions, not a promise of all historical or future clients.

## Publish / ingest

Twine multipart uploads validate distribution filenames/project/version and payload integrity; atomically add the release file set with provenance.

## Consume and source support

pip install/download from local/remote/replica Simple endpoints; serve metadata sidecars when advertised.

## Resolution policy

package-owner per normalized project name

## Format-specific integrity and metadata

Rewrite file URLs while preserving hashes and sidecar relationships; authorization precedes enumeration. Distinct normalized names cannot bypass ownership.

## Explicit non-goals

PyPI account/UI/XML-RPC emulation and building sdists on the server are excluded.

## Required client scenarios

- [ ] Upload wheel and sdist, then pip install with hashes and Python-version filtering from replica.
- [ ] Reject normalized-name conflict, hash mismatch and unauthorized upload; yanked metadata survives replication.

All [shared source, cache, auth, lifecycle, search, replication and conformance requirements](common.md) also apply. Task T1 closes contract definition only; T2–T4 remain implementation and evidence work.

## Delete and unlist (artifact core)

All deletion goes through `artifact.Service.Delete/Unlist/Relist`: delete permission, feed/namespace delete policy (`allowed`, `unlist_only`, `denied`, immutable releases), audit and outbox in the same transaction, replication tombstones, cache invalidation hook; bytes are only reclaimed later by garbage collection.

API only (clients have no delete/yank): `DELETE files/{project}/{filename}` deletes; `PUT`/`DELETE files/{project}/{filename}/yanked` yanks (PEP 592 `yanked:true`) and restores.

Management API: `DELETE /api/v1/feeds/{id}/packages/{component}/versions/{version}?action=delete|unlist|relist`, `DELETE /api/v1/feeds/{id}/assets/{asset}`, MCP `delete_package_version`, console package drawer.
