## Concrete parent integration API

- `NewProvider(ctx, ProviderConfig{Key, Issuer, ClientID, ClientSecret, RedirectURI, AllowedEndpoints}) (*Provider,error)`: trusted startup config only. AllowedEndpoints must explicitly list exact authorization, token and JWKS URLs, HTTPS only. Discovery cannot authorize new outbound endpoints. RedirectURI has no query/fragment. RS256 verification, cached/rotating JWKS.
- `Sessions{DB: pool, InstanceID: instanceID, MaxAge: 8*time.Hour, IdleTimeout: 30*time.Minute}`; zero durations use these defaults, larger values rejected.
- `Client{Provider:p, Sessions:s, Origin:"https://console.example"}` exposes `Login`, `Callback`, `SessionInfo`, `Logout` HTTP handlers. Mount callback on exact configured path. Callback returns JSON session + csrf_token and sets Secure/HttpOnly/SameSite=Lax __Host cookies. SessionInfo restores CSRF token after reload. No credentialed cross-origin CORS.
- `Client.AuthenticateRequest(r) (Session,error)` checks secure browser session, exact Origin and X-CSRF-Token on mutations. Returned Session has PrincipalID/InstanceID/ExpiresAt. Parent must feed principal into existing authorization pipeline; no permissions inferred here. Restrict to management routes, not package clients. Parent's public URL/forwarded-host trust boundary remains required.
- `Sessions.BindIdentity(ctx, issuer, subject, principalID)` requires prior administrative authorization and existing enabled user principal; no implicit provisioning/admin/email trust. Existing binding cannot be overwritten.
- `Sessions.Revoke(ctx, rawCookie)` and `Cleanup(ctx)` support local revocation/maintenance. Logout is POST + CSRF, revokes local session; does not claim upstream IdP global logout.
- Parent must wire audit/security events and request-rate limits at route boundary. No edits to identity/main/config/OpenAPI by this agent.

## Follow-up APIs (audit / external identities / throttle)

- `Sessions.IssueExternal(ctx, issuer, subject) (Session, raw, csrf, error)` is implemented. Trusted verified SAML/LDAP adapter only; same explicit binding/enabled existing user checks as OIDC; creates no principals or roles. Issuance + audit + outbox commit together before secrets are returned.
- `Sessions.BindIdentityAs(ctx, actor identity.Principal, issuer, subject, principalID) error` loads DB-owned `identity.Roles`, calls shared `Policy.Authorize` for instance `Admin`, checks actor enabled under transaction lock, inserts binding + audit + outbox transactionally. Actor must come from authenticated middleware; no actor UUID-only authorization. `BindIdentity` remains privileged internal setup compatibility only, now also transactional/audited (null actor denotes privileged local setup).
- `Sessions.Revoke` now commits deletion + audit + outbox atomically. Audit/outbox failure rolls mutations back and returns redacted ErrUnavailable.
- `Sessions.RecordLoginFailure(ctx)` writes independent bounded durable audit/outbox using context.WithoutCancel; records only fixed action, instance, and null principal. Login/Callback use it automatically. Failure to persist returns 503; no raw errors/credentials are logged or returned.
- Each long-lived `*Client` now contains a mutex-bearing limiter: do not copy after use. Login/Callback share 20 attempts or 5 failures per peer per minute, at most 4096 peer entries; capacity saturation fails closed. RemoteAddr IP only (ports normalized); ignores forwarding headers. Reverse proxies intentionally share their actual peer budget. Throttled attempts return 429 and Retry-After:60 without unbounded audit writes. These are process-local limits under A01 single-process serving; parent route/global request limits remain appropriate.
- No new external HTTP issuance helper: parent may use returned raw/CSRF plus exported SessionCookie/CSRFCookie with Secure, HttpOnly, SameSite=Lax, Path=/, no Domain and session expiry. Existing OIDC callback handles cookie rotation. Parent external flows must rotate prior sessions and apply protocol replay/origin controls.
