# Governance

Kuvryn Ant uses a simple maintainer model while the project is young.

## Roles

- **Maintainers** review and merge pull requests, triage issues, cut releases and
  set the roadmap. They are listed in [.github/CODEOWNERS](.github/CODEOWNERS).
- **Contributors** are everyone who opens issues, reviews, writes code or
  documentation. Contributors who make sustained, high-quality contributions can be
  invited to become maintainers by consensus of the existing maintainers.

## Decisions

Day-to-day decisions are made in pull requests and issues. A change is merged when
a maintainer approves it and CI passes. Larger decisions (new formats, storage or
API contract changes, breaking changes, governance changes) are proposed in an issue
and decided by maintainer consensus; if consensus cannot be reached, the project
lead decides. Durable decisions are recorded in the repository (planning documents
and the changelog).

## Code of conduct

All participants follow the [Code of Conduct](CODE_OF_CONDUCT.md). Maintainers
enforce it.

## Trademarks

The Kuvryn Ant name and logo identify this project. You may use them to refer to
the project, but not in a way that suggests endorsement or for a fork distributed
under the same name.

## Changes to this document

Changes to governance are made by pull request and require approval from a majority
of maintainers.
