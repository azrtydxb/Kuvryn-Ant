# P2 (Eclipse)

The p2 adapter serves Eclipse p2 repositories: the update sites that the Eclipse IDE, the p2 director and Maven Tycho install bundles and features from. A feed can hold repositories you upload as a zip. It can also proxy and cache an upstream p2 repository such as one on `download.eclipse.org`.

Endpoint: `https://ant.example.com/feeds/<slug>/p2` (feed format `p2`). Use this URL as the update-site or repository location.

## Support matrix

| Publish                                | Consume                     | Remote (pull-through)                             | Replica                       | Notes                                  |
| -------------------------------------- | --------------------------- | ------------------------------------------------- | ----------------------------- | -------------------------------------- |
| Yes, `PUT repository.zip` (feed admin) | Yes, simple p2 repositories | Yes, simple (non-composite) upstream repositories | Yes, through core replication | No composite repositories, no Pack200. |

Served routes (all under `/feeds/<slug>/p2/`):

| Method        | Path                                                 | Purpose                                 |
| ------------- | ---------------------------------------------------- | --------------------------------------- |
| `GET`, `HEAD` | `p2.index`                                           | Repository index                        |
| `GET`, `HEAD` | `content.xml`, `content.jar`, `content.xml.xz`       | Metadata repository (installable units) |
| `GET`, `HEAD` | `artifacts.xml`, `artifacts.jar`, `artifacts.xml.xz` | Artifact repository                     |
| `GET`, `HEAD` | `plugins/<id>_<version>.jar`                         | Bundles (`osgi.bundle`)                 |
| `GET`, `HEAD` | `features/<id>_<version>.jar`                        | Features (`org.eclipse.update.feature`) |
| `GET`, `HEAD` | `binary/<id>_<version>`                              | Binary artifacts                        |
| `PUT`         | `repository.zip`                                     | Upload a zipped p2 repository           |

## Limits

- An upload can be at most 1 GiB. The XML indexes can be at most 128 MiB, and an upload can hold at most 20,000 entries. Concurrent uploads per process are bounded by `ANT_UPLOAD_SLOTS`.
- On upload, every artifact's `download.checksum.sha-256` (or `download.md5`) and `download.size` are checked. Artifact references from installable units must resolve, either within the upload or against artifacts already in the feed. Artifacts with a `format` property (Pack200) are rejected.
- The `requires` closure of installable units is not checked, only the artifact closure.
- Artifacts are immutable. The same IU or artifact id and version with different bytes answers 409. The feed's indexes are merged deterministically from all uploaded repositories.
- There is no delete and no retention for p2 content yet. A `DELETE` is refused.
- Composite repositories (`compositeContent.xml`, `compositeArtifacts.xml`) cannot be uploaded or proxied.
- Responses carry `Cache-Control: private, no-store`.

::: warning Gap
The conformance harness checks the protocol with `curl`: upload, the index files, and the downloaded jar's checksum. The Eclipse p2 director, the Eclipse IDE and Tycho have not been run against the adapter. The client configuration below is the standard syntax for those clients, not a verified run.
:::

## Create the feed

In the console, open **Feeds**, choose **New feed** and pick format `p2`. Attach a local source and make it the publish target, or attach a remote source and set its origin on the **Upstream** tab.

```sh
export ANT=https://ant.example.com
H="Authorization: Bearer $ANT_TOKEN"; J='Content-Type: application/json'

SRC=$(curl -fsS -X POST $ANT/api/v1/sources -H "$H" -H "$J" -H 'Idempotency-Key: p2-local-1' \
  -d '{"name":"p2-local","kind":"local","format":"p2"}' | jq -r .id)
curl -fsS -X POST $ANT/api/v1/feeds/batch -H "$H" -H "$J" -H 'Idempotency-Key: p2-feed-1' -d @- <<JSON
{"slug":"eclipse-internal","format":"p2","source_ids":["$SRC"],
 "publish_policy":{"default_source_id":"$SRC","rules":[]}}
JSON
```

## Remote upstreams

The origin of a remote p2 source is the root of a simple p2 repository, the directory that holds `p2.index`, `content.*` and `artifacts.*`. The trust model matches APT and RPM:

- The adapter serves `p2.index`, `content.{xml,jar,xml.xz}` and `artifacts.{xml,jar,xml.xz}` from upstream byte for byte, through the metadata cache. Above the cache limit it streams them instead. They are never rewritten or merged, and a variant the upstream lacks answers 404.
- Files under `plugins/`, `features/` and `binary/` are served only if the upstream artifacts index lists them. Before the first byte is served, the bytes are checked against `download.checksum.sha-256`, or against `download.md5` plus `download.size`. They are then cached. Packed (`format`) artifacts and artifacts without a checksum are skipped. Signed JAR bytes are never touched, so the client's own signature checks still apply.
- A repository has one owner. A locally uploaded snapshot is never extended from upstream.

Release trains such as `https://download.eclipse.org/releases/<train>/` are composite repositories that point at timestamped child repositories, so the train URL itself cannot be the origin. Use the child repository that `compositeArtifacts.xml` names:

| Upstream                                     | `origin`                                                    | `redirect_origins` |
| -------------------------------------------- | ----------------------------------------------------------- | ------------------ |
| Eclipse release train (one child repository) | `https://download.eclipse.org/releases/<train>/<timestamp>` | none               |
| Any simple p2 site                           | `https://updates.example.com/p2/myproduct/1.0`              | none               |

```sh
# find the child repository of a release train
curl -fsS https://download.eclipse.org/releases/2024-06/compositeArtifacts.xml | grep '<child '

REM=$(curl -fsS -X POST $ANT/api/v1/sources -H "$H" -H "$J" -H 'Idempotency-Key: p2-eclipse-1' \
  -d '{"name":"eclipse-2024-06","kind":"remote","format":"p2"}' | jq -r .id)
REV=$(curl -fsS -D- -o /dev/null $ANT/api/v1/sources/$REM -H "$H" | tr -d '\r' | awk 'tolower($1)=="etag:"{print $2}')
curl -fsS -X PUT $ANT/api/v1/sources/$REM/remote-config -H "$H" -H "$J" -H "If-Match: $REV" \
  -H 'Idempotency-Key: p2-eclipse-cfg-1' -d '{
  "origin":"https://download.eclipse.org/releases/2024-06/<timestamp>","redirect_origins":[],
  "allow_private":false,"timeout_seconds":120,
  "cache":{"metadata_ttl_seconds":3600,"negative_ttl_seconds":60,"stale_if_error_seconds":86400,
           "max_entries":10000,"max_bytes":268435456}}'
curl -fsS -X POST $ANT/api/v1/feeds/batch -H "$H" -H "$J" -H 'Idempotency-Key: p2-eclipse-feed-1' -d @- <<JSON
{"slug":"eclipse-2024-06","format":"p2","source_ids":["$REM"]}
JSON
```

::: warning Gap

- p2 remote pull-through is covered by integration tests only. It has not been run against `download.eclipse.org`.
- The upstream `artifacts.*` file is served verbatim. If it carries a `p2.mirrorsURL` property, as `download.eclipse.org` repositories do, p2 clients may fetch artifacts straight from Eclipse mirrors instead of through the feed. With Tycho, `-Declipse.p2.mirrors=false` turns mirror selection off. This interaction has not been tested.
- Indexes come from the in-process metadata cache, so there is no durable offline index. Cached files stay downloadable during an outage.

:::

## Client configuration

### Credentials

Use HTTP Basic with any username and an Ant token (service token or personal access token) as the password, or send the token as a Bearer token. Reading needs the `read` permission. Uploading needs the `admin` action on the feed. Anonymous reads are possible only if the feed has anonymous reads enabled and the client auth policy allows `anonymous` (see [Package client auth](../identity/client-auth.md)).

::: code-group

```xml [Tycho (pom.xml)]
<repositories>
  <repository>
    <id>ant-eclipse</id>
    <layout>p2</layout>
    <url>https://ant.example.com/feeds/eclipse-2024-06/p2</url>
  </repository>
</repositories>
```

```xml [Tycho (~/.m2/settings.xml)]
<settings>
  <servers>
    <server>
      <id>ant-eclipse</id>
      <username>token</username>
      <password>${env.ANT_TOKEN}</password>
    </server>
  </servers>
</settings>
```

```sh [p2 director]
eclipse -nosplash -application org.eclipse.equinox.p2.director \
  -repository https://ant.example.com/feeds/eclipse-internal/p2 \
  -installIU org.example.bundle
# the director prompts for, or reads from Eclipse secure storage, the HTTP Basic credentials
```

:::

In the Eclipse IDE, open **Help > Install New Software > Add...**, enter the feed URL, and give a username and token when prompted. Eclipse keeps them in its secure storage.

### Publish

Zip a p2 repository, as produced by Tycho (`target/repository/`) or by the p2 publisher, so that `content.*` and `artifacts.*` sit at the root of the zip next to `plugins/`, `features/` and `binary/`:

```sh
(cd target/repository && zip -r ../repository.zip .)
curl -fsS -u token:$ANT_TOKEN -X PUT --data-binary @target/repository.zip \
  https://ant.example.com/feeds/eclipse-internal/p2/repository.zip
```

The upload commits atomically as one content-addressed manifest. Its units and artifacts then appear in the feed's merged `content.*` and `artifacts.*`.

### GitHub Actions

Get a short-lived token with the OIDC exchange in [GitHub Actions](../ci/github-actions.md) (trust rules: [GitHub OIDC trust](../identity/github-oidc.md)). Expose it as `ANT_TOKEN` for the Tycho `settings.xml` above, or for the `curl` upload.

## Troubleshooting

| Symptom                                           | Cause                                                                                                                                         |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `401`                                             | No credentials or wrong credentials. In Tycho, the `<server><id>` must equal the repository `<id>`.                                           |
| `403`                                             | The token lacks read permission, the client auth policy refuses the credential type, or you uploaded without feed admin.                      |
| `400` on upload                                   | Not a zip, no `content.*` or `artifacts.*` at the root, a checksum or size mismatch, an unresolved artifact reference, or a Pack200 artifact. |
| `409` on upload                                   | An IU or artifact with the same id and version already exists with different bytes.                                                           |
| `404` for `compositeContent.xml` on a remote feed | The origin is a composite repository. Point it at a child repository.                                                                         |
| `404` for a bundle on a remote feed               | The upstream artifacts index does not list it, or lists it without a checksum or as a packed artifact.                                        |
| `X-Kuvryn-Cache: stale` and `Warning: 110`        | An index came from the metadata cache after its TTL because upstream was unreachable.                                                         |
